# Connector troubleshooting

| Symptom | Check | Next step |
|---|---|---|
| Client cannot discover auth | Is `/.well-known/oauth-protected-resource/mcp` reachable on the public origin? | Route discovery paths and `/mcp/oauth/*` through the same proxy as `/mcp`. |
| Discovery advertises localhost | Node adapter origin differs from public URL | Set the exact public HTTPS origin; restart the app. |
| `invalid_client` | Missing registration, wrong configured profile, or missing `clientStore` | Use DCR for public clients or resolve the pre-registered client; keep registration enforcement on. |
| Callback rejected | Callback is not an exact allowlisted URI | Add the callback shown by the client to `extraRedirectUris`; do not allow arbitrary hosts. |
| Browser shows an approval page | A login session exists but consent is still required | Approve in the browser. Do not expect `/authorize` to redirect immediately. |
| Login loops | Cookie domain/path/Secure flags do not match public host | Inspect your app's session handling and use a consistent origin. |
| `invalid_redirect_uri: no allowed redirect_uris` on `/register` | The connector's callback is not in the redirect policy. On `createMcpApp`, ChatGPT needs `"codex"` in `clients`; on `createOAuthRouter`, set `redirect` | Read the `register_rejected` entry in your `audit` sink: `reason` lists the callbacks that were asked for. Anyone can write these entries, and a long list is cut: allow a callback only after it matches the one the vendor publishes |
| `invalid_grant` | Expired/replayed code, wrong verifier or resource, or your `mintAccessToken` / `refreshAccessToken` threw `AccessDeniedError` (description "access denied") | Start a fresh authorization flow and keep verifier and resource consistent. For "access denied", read the `access_denied` entry in your `audit` sink: `reason` holds the message you threw (without an `audit` port it goes nowhere). |
| `/token` returns 500 `server_error` when a user should simply be refused | A `mintAccessToken` or `refreshAccessToken` port threw a plain `Error` | Throw `AccessDeniedError` for deliberate refusals; any other throw stays a 500. |
| Tool request returns 401 | Token expired, verification failed, or audience mismatch | Verify signature/expiry in app auth and return the requested MCP audience. |
| Tool request returns 403 | Tool scope missing | Grant and return the required scopes from token verification. |
| Wrong user's data | Data query ignores authenticated identity | Filter by verified principal and tenant; never trust a tool argument for ownership. |
| Switching login does not switch connector user | Connector retains its previously issued token | Disconnect and reauthorize with the intended account. |
| Initialization works but tools fail | Initialize is public | Test authenticated `tools/call`; initialize alone proves no auth flow. |
| `unauthorized_client: CIMD client_id could not be resolved` | The connector is told one generic error on purpose; the cause is in your audit sink | Read the `cimd_resolve_failed` entry: `reason` is `<code>[: detail] (authorize\|token/revoke)`. `http_status: status 403` = the document host refused the fetch; `auth_method_unsupported` = its document excludes `none`; `dns_failed (ENOTFOUND)` / `dns_unavailable` = no DNS from this runtime, pass `cimdLookup`; `blocked_address` = it resolves to a non-public address; `timeout` = the host did not answer, or stalled mid-body, within 10 s. Pass `cimdCache` so refresh does not re-fetch. |
| Connector asks to reconnect about every hour | The access token expired and there is no refresh token (`signedTokenAuth` default) | Set `refreshTtlSeconds` with `codeStore` and `isUserActive`, or raise `ttlSeconds`. See [Sessions and expiry](security.md#sessions-and-expiry) |
| `401` with `error="invalid_token"` | A bearer was sent and rejected, whatever the reason ([Sessions and expiry](security.md#sessions-and-expiry)) | Reconnect. Check expiry and audience, then your `isUserActive` |
| Approve shows "This approval request expired" / "Your sign-in changed or expired" / "already submitted" | Ticket older than 5 minutes, the app session ended before Approve, or the form was posted twice | Start the connection again from the connector |
| `400` on `/mcp` about the protocol version | The `MCP-Protocol-Version` header names a version the server does not serve | Send 2024-11-05, 2025-03-26, 2025-06-18, 2025-11-25 or 2026-07-28 (see [reference](reference.md#2026-07-28-requests)). An unknown version in `initialize` is answered with the default, 2025-06-18. |
| A tool is missing from `tools/list`, or `tools/call` says unknown tool | `hideToolsOutsideScope` hides tools outside the caller's scopes | Grant the scope, or turn the option off. With `"strict"` a hidden tool answers as unknown (`-32602`), not `403`. |
| Construction throws "unsupported JSON Schema keyword at ..." | A tool schema uses a keyword the evaluator does not honour, a non-local `$ref`, or a keyword such as `definitions` whose draft-07 meaning differs | Remove it, or set `validateArgs: false` (`validateOutput: false` for an `outputSchema`). See [JSON Schema 2020-12](reference.md#json-schema-2020-12) |
| Construction throws "unsupported regex syntax for pattern: ..." | A `pattern` or `patternProperties` key uses a construct the built-in matcher does not support (backreference, lookaround, `\p{...}`, inline flags), is invalid, or compiles to over 2000 instructions | Simplify the pattern, or pass `schemaValidator` and own the check. See [JSON Schema 2020-12](reference.md#json-schema-2020-12) |
| Construction throws "(unsupported dialect)" | `$schema` is not 2020-12, 2019-09 or draft-07 | Use one of those, or drop `$schema` |
| A tool answers "Tool returned an invalid result" | Its `structuredContent` is missing or breaks the tool's `outputSchema` | Pass `onOutputViolation` and read the violations in your server log. See [Tool results](reference.md#tool-results-and-annotations) |
| `-32020` on `tools/call` naming an `Mcp-Param-*` header | A 2026-07-28 client sent a header that is missing, malformed or different from the argument it mirrors (`x-mcp-header`) | Fix the client. The audit `error` is `param_header_mismatch` |
| A 2026-07-28 client sees a plain text tool, no UI, and `resources/read` of the `ui://` URI is unknown | The client did not declare `io.modelcontextprotocol/ui` with `mimeTypes` including `text/html;profile=mcp-app` in `clientCapabilities.extensions` | Declare the extension on the client. See [Extension negotiation](mcp-apps.md#extension-negotiation) |
| A client on 2024-11-05, 2025-03-26, 2025-06-18 or 2025-11-25 gets no `structuredContent`, or no `outputSchema` in `tools/list` | Those versions only get an object `structuredContent`, and `tools/list` leaves out an `outputSchema` whose root is not an object | Put the answer in `content` as text too. See [Tool results](reference.md#tool-results-and-annotations) |

Read [security.md](security.md) before replacing production token verification with example code. When you open an issue, share sanitized errors only, never access tokens or session cookies.
